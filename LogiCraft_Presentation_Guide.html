Project Mission Statement
LogiCraft is an integrated fleet and logistics management system that combines real-time GIS telematics tracking, freight consignment lifecycle management, regional warehouse capacity planning, and multi-modal passenger transit ticketing into a unified, enterprise-ready platform.

3. Technical Architecture & Design Decisions

Backend & ORM Design

Built with Python 3.13 & Django 5.x using clean Model-View-Template separation. Data integrity is enforced using foreign key cascades, unique tracking number generators, and decimal-precision financial calculations.

GIS & Mapping Strategy

Integrated Leaflet.js with Esri World Street Map, OpenStreetMap, and Esri Satellite Imagery. Completely eliminates third-party API keys, billing accounts, and avoids OSM volunteer server 403 blocks.

Role-Based Access (RBAC)

Extended AbstractUser with a custom Role enumeration (ADMIN, LOGISTICS_MANAGER, DRIVER). Decorators restrict critical endpoints like vehicle onboarding and CSV exports.

Reporting & Data Export

Native HTTP streaming using Python's csv writer generates RFC-4180 compliant CSV files with live metadata headers, allowing instant data extraction into BI tooling.

5. Evaluator Q&A Cheat Sheet (Common Viva Questions)

Q: How does the map render live locations without paid Google Maps APIs?

Answer: We use Leaflet.js with Esri World Street Map and OpenStreetMap raster tile servers. Leaflet downloads raster tiles asynchronously over HTTPS with zero billing dependencies, while Django ORM serializes model coordinates to GeoJSON-compatible objects on the client.

Q: How are coordinates and vehicle locations updated?

Answer: The Vehicle model stores float fields for latitude and longitude alongside timestamps and current location descriptions. In production, IoT telematics devices (OBD-II / GPS transponders) send telemetry updates to an internal REST webhook endpoint which updates these coordinates.

Q: How is data protected between different user roles?

Answer: Through Django's built-in session framework coupled with custom view decorators (e.g. @login_required and role verification checks). Views evaluate request.user.role before granting access to sensitive views like fleet modifications or financial waybills.

Q: How does the system scale to handle large datasets?

Answer: We use Django database query optimizations like select_related and prefetch_related to eliminate N+1 query overhead across relationships (e.g. Driver-to-Vehicle, Shipment-to-Warehouse). CSV exports utilize Python generators to stream rows without consuming server RAM.
